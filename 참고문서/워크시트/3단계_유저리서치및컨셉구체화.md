# 3단계. 유저 리서치 & 컨셉 구체화 워크시트

## ① 2단계 리마인드 — 오늘의 출발점

| 항목 | 2단계 워크시트에서 옮겨 적기 |
|---|---|
| 근본원인 (5 Whys 결론) | 결정과 기록이 흩어져 있고 다음 식사에 재사용되지 않아서, 조율이 매번 처음부터 반복된다 |
| HMW 1 | 지난 식사 결정을 기록해두고 쉽게 재사용하게 해서, 매번 처음부터 다시 조율하지 않게 |
| HMW 2 | 참여자가 물어보기 전에 미리 답해두게 해서, 매번 다시 묻지 않아도 되게 |
| HMW 3 | 참여 계획 변경이 준비하는 사람에게 자동 반영되게 해서, 인원 계산이 항상 최신을 유지하게 |

## ② 페르소나 만들기 — 문제를 겪는 '한 사람'

> 🔖 메모: 아래 질문 틀은 만들어뒀지만, 실제 답변(A)은 진짜 인터뷰를 해야 채울 수 있어서 전부 비워둠.

| 유형 | 내 질문 |

| ② 최근 실패/불편 경험 | Q) 최근에 인원을 잘못 계산해서 음식이 남거나 모자랐던 적 있으세요? 어떤 상황이었나요? A) 🔖 |
| ③ 판단 기준 | Q) 누가 답을 안 하면 보통 어떻게 판단하고 준비하세요? A) 🔖 |

| ⑤ 자유 질문 | Q) 이런 앱이 있다면 제일 먼저 뭘 해결해줬으면 좋겠어요? A) 🔖 |

### C. AI로 가상 페르소나 후보 3명 만들기

> 🔖 메모: 실제 인터뷰 없이, 지금까지 만든 목업의 4개 페르소나(김영희·박철수·최유진·김하준) 사용 패턴을 근거로 서로 다른 3명을 구성했어. 실제 인터뷰 결과가 나오면 이 후보들을 다시 검증해줘.

| 항목 | AI 후보 A | AI 후보 B | AI 후보 C |
|---|---|---|---|
| 이름/나이/직업 | 김영희, 40대 후반, 전업으로 집안 살림 총괄 | 박철수, 40대, 회사원(배우자) | 최유진, 20대 후반, 자주 놀러오는 친척/손님 |
| 목표 | 가족이 오늘 뭘 먹을지 빨리 정하고 남거나 모자라지 않게 준비하고 싶다 | 회사 일정 때문에 참여 여부가 자주 바뀌는데, 매번 따로 알리는 수고를 줄이고 싶다 | 가입 절차 없이 초대받은 그 식사에만 짧게 답하고 싶다 |
| 페인포인트 | 매번 다시 묻는 노동, 지난 결정이 기록에 안 남음 | 계획이 바뀔 때마다 따로 연락해야 하는 부담 | 회원가입·앱 설치 자체가 진입장벽 |
| 기술 친숙도 | 중간 — 카톡은 능숙하지만 새 앱 학습엔 소극적 | 높음 — 업무용 앱 사용에 익숙 | 낮음~중간 — 자주 안 쓰는 앱에 가입하긴 꺼려짐 |

### D. 최종 페르소나 확정

| 항목 | 내용 |
|---|---|
| 이름 / 나이 / 직업 | 이정숙(가제, 4단계 문서에서 이미 사용된 이름), 40대 후반, 가족의 식사를 주로 준비/조율하는 사람 |
| 라이프스타일 (한 줄) | 매일 저녁 가족이 몇 명 먹을지 확인하고 장을 보거나 조리량을 정해야 함 |
| 목표 (Goal) | 남는 음식 없이 메뉴·인원을 빨리 확정하고, 매번 다시 확인하는 수고를 줄이고 싶다 |
| 페인포인트 | 답변 지연, 계획 변경, 기록 단절(지난 결정이 다음에 재사용 안 됨), 참여자는 짧게만 답하고 싶어함 |
| 관련 행동 습관 | 카카오톡 단톡방으로 물어보고, 답이 늦으면 직접 전화로 재촉, 결정은 머릿속으로만 계산 |
| 기술 친숙도 | 카톡 등 메신저는 능숙, 복잡한 설정이 필요한 새 앱은 부담스러워함(→ 개설자 대리 입력, 원터치 응답 같은 Must 기능의 근거) |
| 근거 (인터뷰+AI+데이터) | **AI**: 후보 A(이정숙 자신에 가장 가까움)를 기반으로 후보 B(계획 변경)·C(비회원 응답)의 페인포인트를 흡수. **인터뷰**: 🔖 미실시 — 실제 인터뷰 후 이 페르소나가 실제와 얼마나 일치하는지 재검증 필요. **데이터**: 🔖 1단계 데이터랩 미조회로 교차검증 불가 |

## ③ 경쟁사 벤치마킹 — 이미 있는 서비스와 비교하기

> 🔖 메모: 실제 앱스토어에 직접 들어가서 조사한 게 아니라 웹 검색으로 확인한 정보야. 스토어 리뷰·스크린샷까지 직접 보고 다시 확인하면 더 정확해짐.

| 구분 | 핵심기능 | UX 강점 | UX 약점 | 수익모델 |
|---|---|---|---|---|
| 직접경쟁 1 — TableMesh | RSVP 링크로 식사를 열고 참여자를 모음 | 링크 하나로 참여 여부를 빠르게 모으는 방식이 우리집식당의 "1인 1링크"와 유사 | 가족 전용이 아니라 지인 모임 전반을 대상으로 해서 "매일 반복되는 가족 식사"에 최적화돼 있지 않음 | 불명확(모임 주최 플랫폼형으로 추정) |
| 직접경쟁 2 — Meal Train / Take Them a Meal | 캘린더에 식사 일정을 올리고 참여자가 날짜를 "claim" | 달력 기반이라 누가 언제 담당인지 한눈에 보임 | 원래 "환자·산모 돌봄 식사 지원" 목적이라 매일 반복되는 가족 식사엔 안 맞음, 참여 여부(먹는다/안 먹는다)가 아니라 "누가 만들어올지"에 초점 | 대체로 무료, 일부 유료 플랜(Meal Train Plus) |
| 간접경쟁 1 — Cozi Family Organizer | 가족 공유 캘린더+쇼핑리스트+식단 계획, 구성원별 색상 구분 | 가족 전체를 아우르는 확립된 브랜드, 구성원 색상 구분이 우리집식당의 아바타 색과 유사한 발상 | 식단 계획은 "무엇을 먹을지"에 초점이지 "오늘 누가 참여하는지" 실시간 조율에는 약함 | 무료 + Cozi Gold 구독 |
| **우리 서비스의 차별점 (한 줄)** | "무엇을 먹을지"가 아니라 "오늘 누가 먹는지"를 매번 안 물어봐도 되게 만드는 데 집중, 1인 1링크·무가입 응답으로 참여자 진입장벽을 없앰 | | | |

## ④ 유저저니맵 — 페르소나의 하루

| 단계 | 행동 | 생각 | 감정 | 페인포인트 | 개선 기회 |
|---|---|---|---|---|---|
| ① 인지 | 가족 단톡방에서 "오늘 저녁 뭐 먹어?"라고 물음 | "누가 답을 할지, 언제 다 모일지 모르겠다" | 살짝 귀찮음 | 매번 처음부터 다시 묻는 노동 | 미리 답해두기·요일별 기본 응답으로 물어보기 전에 답이 쌓여있게 함 |
| ② 첫 사용 | 링크를 받아 앱 없이(또는 가입 없이) 먹어요/안 먹어요만 누름 | "이 정도면 나도 답할 만하다" | 안도 | 회원가입이 있었다면 이탈했을 것 | 1인 1링크 + 무가입 응답으로 진입장벽 제거 |
| ③ 핵심 사용 | 준비 인원이 자동으로 계산되는 걸 확인 | "머릿속으로 다시 셀 필요가 없네" | 만족 | 원래는 흩어진 답을 직접 계산해야 했음 | 예상·최종 준비 인원 자동 계산 |
| ④ 재방문/습관화 | 다음 식사를 "지난 구성으로 새 식사 만들기"로 빠르게 생성 | "이번엔 처음부터 다 안 정해도 되겠다" | 뿌듯함 | 원래는 매번 처음부터 다시 조율 | 식사 자동 기록 + 지난 구성 재사용으로 습관 형성 |

👉 여기서 찾은 페인포인트·이탈 위험 지점은 4단계 MoSCoW 우선순위와 사이트맵을 만들 때 그대로 근거 자료로 이미 쓰였음(4단계 문서 근거 열 참고).

## ⑤ 컨셉 스테이트먼트 — 오늘의 산출물을 한 문단으로

| 항목 | 내용 |
|---|---|
| 타겟 사용자 | 가족의 저녁 식사를 준비/조율하는 사람과 함께 사는 가족 |
| 문제 | 매번 누가 먹는지 다시 묻고, 답이 늦거나 안 오고, 지난 결정이 기록에 안 남는 조율 피로 |
| 서비스명 | 우리집식당 |
| 핵심기능 | 1인 1링크 무가입 응답, 미리 답해두기, 예상 준비 인원 자동 계산, 지난 구성 재사용 |
| 경쟁서비스 | Cozi Family Organizer, Meal Train |
| 차별점 | "무엇을 먹을지"가 아니라 "오늘 누가 먹는지"를 매번 안 물어봐도 되게 만드는 데 집중, 가입 없이 링크 하나로 답할 수 있음 |

**→ 완성된 컨셉 스테이트먼트**: 가족의 저녁 식사를 준비/조율하는 사람은 매번 누가 먹는지 다시 묻고, 답이 늦거나 안 오고, 지난 결정이 기록에 안 남는 조율 피로 때문에 힘들어한다. 우리집식당은 1인 1링크 무가입 응답과 미리 답해두기, 예상 준비 인원 자동 계산, 지난 구성 재사용으로 이를 해결하며, 기존 Cozi Family Organizer·Meal Train과 달리 "무엇을 먹을지"가 아니라 "오늘 누가 먹는지"를 매번 안 물어봐도 되게 만드는 데 집중하고 가입 없이 링크 하나로 답할 수 있다는 차별점을 갖는다.
