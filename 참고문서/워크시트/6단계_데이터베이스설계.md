# 6단계. 데이터베이스 설계

> 지금은 `localStorage` 41개 키로 전체 흐름을 흉내내고 있음(전 화면 코드에서 직접 추출·확인). 아래는 이걸 실제 서비스 DB(Supabase 기준)로 옮긴다면의 설계.

## ① 데이터 항목 도출

| 테이블명 | 항목(컬럼) | 타입 | 출처 화면 |
|---|---|---|---|
| households (가구) | id, name, owner_member_id, created_at | uuid, 텍스트, uuid, 날짜 | `1-3` 온보딩-가구프로필 |
| household_members (구성원) | id, household_id, name, color, is_owner, is_co_admin | uuid, uuid, 텍스트, 텍스트, 불리언, 불리언 | `1-4` 온보딩-가족구성원, `5-1` 가구 설정 |
| users (계정) | id, email, phone, address, profile_photo_url, nickname | uuid, 텍스트, 텍스트, 텍스트, url, 텍스트 | `1-1` 온보딩-회원가입, `5-3` 설정 |
| meals (식사) | id, household_id, creator_member_id, date, time, meal_type, menu(배열), status | uuid, uuid, uuid, 날짜, 시간, enum(집밥/외식/배달), 텍스트[], enum(draft/confirmed) | `3-2` 식사 만들기, `3-4` 확정 전 요약, `3-5` 오늘의 식탁 완성 |
| meal_participants (참여 응답) | id, meal_id, member_name, status, arrival_time, note | uuid, uuid, 텍스트, enum(attending/absent/pending), 시간, 텍스트 | `3-3` 참여자 응답, `3-1` 내 식탁 |
| advance_answers (미리 답해두기) | id, household_id, member_name, date, status | uuid, uuid, 텍스트, 날짜, enum | `4-1` 홈 달력뷰 |
| weekday_defaults (요일별 기본응답) | id, household_id, member_name, day_index(0~6), status | uuid, uuid, 텍스트, 정수, enum | `5-4` 요일별 기본 응답 |
| recurring_meals (반복 일정) | id, household_id, days(배열), time, meal_type, menu, participants, last_fired_date | uuid, uuid, 정수[], 시간, enum, 텍스트[], 텍스트[], 날짜 | `3-2` 식사 만들기, `3-1` 내 식탁 |
| menu_requests (가족이 먹고싶어요) | id, household_id, member_name, menu, created_at | uuid, uuid, 텍스트, 텍스트, 타임스탬프 | `3-0` 홈 |
| menu_poll (메뉴 투표) | id, meal_id, options(배열), votes(jsonb: 이름→선택) | uuid, uuid, 텍스트[], jsonb | `3-2` 식사 만들기, `3-0` 홈 |
| guestbook_notes (방명록·한마디) | id, household_id, member_name, message, date, created_at | uuid, uuid, 텍스트, 텍스트, 날짜, 타임스탬프 | `3-0` 홈, `4-1` 홈 달력뷰 |
| saved_guests (저장된 손님) | id, household_id, name, visit_count | uuid, uuid, 텍스트, 정수 | `5-1` 가구 설정 |
| saved_places (자주 가는 곳) | id, household_id, name | uuid, uuid, 텍스트 | `3-2` 식사 만들기(외식/배달) |
| household_fridge (냉장고 재료) | id, household_id, name, emoji, freshness, days_added | uuid, uuid, 텍스트, 텍스트, enum(fresh/expiring/urgent), 정수 | `7-1`·`7-2` 냉장고 |
| meal_photos (식사 사진) | id, meal_id, photo_url, caption | uuid, uuid, url, 텍스트 | `8-2` 식사 사진 기록, `5-2` 식사 기록 |
| meal_costs (식사 비용) | id, meal_id, amount | uuid, uuid, 정수 | `5-2` 식사 기록, `8-3` 식비 예산 |
| settlements (정산) | id, meal_id, participants(jsonb), status | uuid, uuid, jsonb, enum | `8-4` 정산 |

| milkit_orders (밀키트 주문 — 제안형) | id, household_id, order_data(jsonb) | uuid, uuid, jsonb | `7-3` 메뉴 추천, `8-1` 밀키트 주문 |
| last_seen (오늘 방문 여부) | id, household_id, member_name, last_seen_date | uuid, uuid, 텍스트, 날짜 | `3-0` 홈 |
| notifications (알림) | id, household_id, recipient_member_name, type, payload(jsonb), unread, created_at | uuid, uuid, 텍스트, enum, jsonb, 불리언, 타임스탬프 | `3-0`/`3-1`/`3-7` 알림 패널 |

## ② Supabase 테이블 설계로 다듬기

| 테이블 A | 테이블 B | 관계 유형 | 설명 |
|---|---|---|---|
| households | household_members | 1:N | 한 가구는 여러 구성원을 가짐 |
| households | meals | 1:N | 한 가구는 여러 식사를 만듦 |
| meals | meal_participants | 1:N | 한 식사는 여러 참여자 응답을 가짐 |
| household_members | meal_participants | 1:N | 한 구성원은 여러 식사에 응답할 수 있음(참여자 이름으로 연결) |
| households | advance_answers / weekday_defaults / guestbook_notes / menu_requests / saved_guests / saved_places / household_fridge / last_seen / notifications | 1:N | 전부 "이 가구 소속" 데이터 |
| meals | menu_poll / meal_photos / meal_costs / settlements | 1:1~1:N | 한 식사에 대한 부가 정보(투표는 여러 식사에 하나씩, 사진·비용·정산은 확정된 식사 하나당) |
| users | household_members | 1:1 (선택적) | 가입한 사용자는 구성원 레코드와 연결되지만, **비회원 손님(무가입 참여자)은 `users` 없이 `household_members`나 `meal_participants`에 이름만 존재할 수 있어야 함** — 이게 이 서비스의 핵심 차별점(1인 1링크 무가입 응답)이라 관계를 강제 1:1로 두면 안 됨 |

## ③ 검증 — 5단계 화면과 대조하기

| 화면 | 화면에 표시되는 정보 | 대응 테이블·컬럼 | 누락 여부 (O/X) |
|---|---|---|---|
| 홈(`3-0`) | 오늘 식탁 좌석·상태, 방명록, 오늘 안 본 사람 | meal_participants, guestbook_notes, last_seen | X |
| 식사 만들기(`3-2`) | 날짜·시간·메뉴·참여자, 반복 설정, 메뉴 투표 | meals, recurring_meals, menu_poll | X |
| 참여자 응답(`3-3`) | 먹어요/안먹어요·도착시간 | meal_participants | X |
| 확정 전 요약(`3-4`) | 예상 인원, 미응답자 | meal_participants(집계 쿼리) | X |
| 요일별 기본 응답(`5-4`) | 구성원별 요일 패턴 | weekday_defaults | X |
| 냉장고(`7-1`) | 재료 목록·신선도 | household_fridge | X |
| 식비 예산(`8-3`) | 월 예산, 식사별 비용 | monthly_budget, meal_costs | X |
| **알림(`3-0`/`3-1`/`3-7`)** | 알림 목록, 안읽음 상태 | notifications | **O · `unread` 상태가 지금은 화면 진입 시 한 번만 계산되고 "읽음 처리" 자체가 DB에 반영되는 흐름이 없음 — `notifications.read_at` 컬럼과 읽음 처리 API가 빠져있음** |
