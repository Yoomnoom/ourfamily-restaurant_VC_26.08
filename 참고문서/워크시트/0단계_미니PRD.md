# 0단계. 미니 프로젝트 — 간단 PRD 작성 가이드

> 🔖 메모: 이 템플릿은 원래 "미니 프로젝트(리허설)"용으로 보이는데, 이번엔 우리집식당 프로젝트 자체를 요약하는 데 그대로 적용했어. 만약 이게 별도의 워밍업 프로젝트를 위한 거였다면 알려줘.

**팀명**: 🔖 미확인 — 알려줘
**팀원**: 윰 (4단계 문서에서 확인된 이름) 🔖 팀원이 더 있는지, 1인 프로젝트인지 확인 필요

## 1. 한 줄 소개

가족이 오늘 저녁 누가 먹는지 매번 카톡으로 묻지 않아도, 한눈에 확인하고 미리 답해둘 수 있는 가족 식사 조율 앱.

## 2. 문제 정의

| 항목 | 내용 |
|---|---|
| 누가 (타깃 사용자) | 매일 가족의 식사를 준비/조율하는 사람(주 페르소나: 이정숙, §3단계 참고) + 응답하는 다른 가족 구성원 |
| 어떤 상황에서 | 가족 구성원의 참여 여부가 매일 바뀌고, 계획도 자주 변경되는 상황에서 |
| 무엇이 불편한가 | 매번 "오늘 저녁 먹어?"를 다시 물어야 하고, 답이 늦게 오거나 안 오고, 지난 결정이 기록에 안 남아 다음 식사도 매번 처음부터 조율해야 함 |

## 3. 핵심 기능

| 기능 | 입력 (사용자가 무엇을 넣으면) | 출력 (앱이 무엇을 돌려주면) |
|---|---|---|
| 식사 만들기 | 날짜·시간·메뉴·참여 대상 | 참여자별 고유 링크 |
| 참여자 응답 | 먹어요/안 먹어요, 도착시간 | 실시간 준비 인원 집계 |
| 미리 답해두기 | 요일별/날짜별 기본 참여 여부 | 다음 식사 생성 시 자동 반영(안 물어봐도 됨) |
| 오늘의 식탁(확정) | 응답 완료 | 확정된 메뉴·인원·시간 요약 + 기록 저장 |
| 요일별 기본 응답 | 구성원별 요일 패턴 | 식사 만들 때 예상 인원 자동 반영 |
| 방명록(한마디) | 짧은 메시지 | 좌석·달력에 남아 다시 볼 수 있는 가족 기록 |

## 4. 필요한 외부 데이터 / API

**없음 — AI 판단만 사용.** 지금은 정적 HTML 목업 + `localStorage`만으로 전체 흐름을 검증하는 단계라 외부 API 연동이 전혀 없음. 실서비스로 전환할 때 필요한 것(Supabase 등)은 6·8단계에서 다룸.

## 5. 오늘의 완성 기준 (Done의 정의)

"가족 중 한 명이 식사를 만들고, 다른 가족이 고유 링크로 들어와 먹어요/안 먹어요를 답하면, 만든 사람이 실시간으로 준비 인원을 확인하고 확정할 수 있다."

→ 이 문장은 이미 참으로 검증됨(정적 목업 35개 화면으로 전체 흐름 동작 확인, `0_개발도구 0. 확인용뷰어`에서 실제로 눌러볼 수 있음).
